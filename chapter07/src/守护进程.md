# 守护进程介绍及 Linux 编程流程

---

## 一、什么是守护进程（Daemon）？

**守护进程（Daemon）** 是在后台运行、不与任何终端（TTY）关联的进程。它通常用于提供某些服务或功能，生命周期长，常驻系统。例如：`sshd`（SSH 服务）、`httpd`（Web 服务）等。

- **特征**：
  - 无控制终端（不与任何用户界面绑定）
  - 通常以 root 或系统用户身份启动
  - 常年后台运行，自动启动/重启
  - 父进程常为 init（PID=1）或 systemd

---

## 二、守护进程的作用

- 实现后台服务（如数据库、Web、消息队列等）
- 系统任务调度（如 `cron`）
- 监控或守护其他进程
- 执行周期性、自动化任务

---

## 三、守护进程的创建流程（Linux 编程流程）

要将普通进程转为守护进程，遵循如下典型编程流程：

### 1. 创建子进程，父进程退出

这样可以让子进程脱离控制终端（shell），成为孤儿进程，由 `init(1)` 或 `systemd` 领养。

```c
pid_t pid = fork();
if (pid < 0) exit(1);   // 创建失败
if (pid > 0) exit(0);   // 父进程退出
// 子进程继续
```

### 2. 创建新会话，脱离原会话和控制终端

```c
setsid();  // 创建新会话，成为会话首进程和进程组组长
```

### 3. 禁止进程重新获得控制终端（可选，双重 fork）

有些情况下，再 fork 一次，并让第一个子进程退出，保证进程无法再获得终端。

```c
pid = fork();
if (pid < 0) exit(1);
if (pid > 0) exit(0);   // 退出第一子进程
// 第二子进程成为最终的守护进程
```

### 4. 修改工作目录为根目录，避免锁定文件系统

```c
chdir("/");
```

### 5. 重设文件权限掩码

```c
umask(0);   // 使进程创建的文件不受限制
```

### 6. 关闭/重定向标准输入、输出、错误

由于守护进程不再与终端交互，需关闭这些文件描述符或重定向到 `/dev/null`：

```c
close(STDIN_FILENO);
close(STDOUT_FILENO);
close(STDERR_FILENO);
// 或者
open("/dev/null", O_RDWR); // stdin
dup(0); // stdout
dup(0); // stderr
```

## 四、完整示例代码

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/types.h>
#include <sys/stat.h>

void daemonize()
{
    pid_t pid = fork();
    if (pid < 0) exit(EXIT_FAILURE);
    if (pid > 0) exit(EXIT_SUCCESS); // 父进程退出

    if (setsid() < 0) exit(EXIT_FAILURE); // 创建新会话

    pid = fork();
    if (pid < 0) exit(EXIT_FAILURE);
    if (pid > 0) exit(EXIT_SUCCESS); // 第一子进程退出

    umask(0);        // 重置文件权限掩码
    chdir("/");      // 修改工作目录

    // 关闭标准输入输出错误
    close(STDIN_FILENO);
    close(STDOUT_FILENO);
    close(STDERR_FILENO);
    open("/dev/null", O_RDWR); // stdin
    dup(0); // stdout
    dup(0); // stderr

    // 守护进程主循环
    while(1) {
        // 执行任务 ...
        sleep(60);
    }
}

int main() {
    daemonize();
    // 守护进程业务逻辑
    return 0;
}
```

---

## 五、注意事项

1. **不要依赖于进程的当前目录和环境变量，建议 chdir("/") 并自行设置环境变量**
2. **注意资源清理和系统日志输出（如用 syslog 记录日志）**
3. **不要直接写屏幕，所有输出重定向或系统日志输出**
4. **可设置 pid 文件防止重复启动**
