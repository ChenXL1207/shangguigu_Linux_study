# 守护进程学习文档

## 什么是守护进程

守护进程（Daemon Process）是 Linux 系统中一种特殊的后台进程，它在系统启动时运行，在系统关闭时终止。守护进程通常在后台运行，不依赖于终端，也没有控制终端。

### 守护进程的特点

1. **后台运行**：守护进程在后台运行，不会占用终端
2. **独立于终端**：即使终端关闭，守护进程仍然继续运行
3. **系统级服务**：通常在系统启动时启动，系统关闭时终止
4. **权限管理**：通常以 root 用户或特定系统用户身份运行
5. **日志记录**：将日志写入文件而不是标准输出

### 常见的守护进程

- `sshd`：SSH 服务守护进程
- `httpd`：Web 服务器守护进程
- `mysqld`：MySQL 数据库守护进程
- `systemd`：系统和服务管理器
- `cron`：定时任务守护进程

## 守护进程的创建步骤

创建一个标准的守护进程需要遵循以下步骤：

### 1. 第一次 fork()

**目的**：创建子进程，让父进程退出，使子进程成为孤儿进程，被 init 进程收养。

```c
pid_t pid = fork();
if (pid < 0) {
    perror("fork");
    exit(EXIT_FAILURE);
}
if (pid > 0) {
    // 父进程退出
    exit(EXIT_SUCCESS);
}
// 子进程继续执行
```

**原理**：
- 父进程退出后，子进程成为孤儿进程
- 孤儿进程会被 init 进程（PID=1）收养
- 子进程不再是进程组的组长

### 2. 调用 setsid()

**目的**：创建新的会话，脱离原来的控制终端。

```c
if (setsid() < 0) {
    perror("setsid");
    exit(EXIT_FAILURE);
}
```

**原理**：
- `setsid()` 会创建一个新的会话
- 调用进程成为新会话的会话组长
- 新会话没有控制终端
- 进程成为新进程组的组长

### 3. 第二次 fork()

**目的**：确保进程不是会话组长，无法重新获取控制终端。

```c
pid = fork();
if (pid < 0) {
    perror("fork");
    exit(EXIT_FAILURE);
}
if (pid > 0) {
    // 父进程退出
    exit(EXIT_SUCCESS);
}
// 子进程继续执行
```

**原理**：
- 会话组长可以重新获取控制终端
- 通过第二次 fork，新的子进程不再是会话组长
- 因此无法重新获取控制终端

### 4. 改变工作目录

**目的**：避免守护进程的工作目录被占用，导致无法卸载文件系统。

```c
if (chdir("/") < 0) {
    perror("chdir");
    exit(EXIT_FAILURE);
}
```

**原理**：
- 守护进程的当前工作目录可能是可挂载的文件系统
- 如果工作目录在被挂载的文件系统上，会导致文件系统无法卸载
- 通常将工作目录改为根目录 `/`

### 5. 设置文件权限掩码

**目的**：确保守护进程创建的文件具有正确的权限。

```c
umask(0);
```

**原理**：
- `umask` 用于设置文件创建时的权限掩码
- 设置为 0 意味着不屏蔽任何权限位
- 守护进程需要完全控制创建的文件权限

### 6. 关闭文件描述符

**目的**：关闭从父进程继承的文件描述符，特别是标准输入、输出、错误输出。

```c
close(STDIN_FILENO);
close(STDOUT_FILENO);
close(STDERR_FILENO);

// 重新打开到 /dev/null
open("/dev/null", O_RDONLY);  // 标准输入
open("/dev/null", O_WRONLY);  // 标准输出
open("/dev/null", O_WRONLY);  // 标准错误输出
```

**原理**：
- 关闭所有从父进程继承的文件描述符
- 重新打开标准输入、输出、错误输出到 `/dev/null`
- 防止守护进程的 I/O 操作影响终端

### 7. 处理信号

**目的**：正确处理系统信号，实现优雅退出。

```c
void signal_handler(int signum) {
    switch(signum) {
        case SIGTERM:
        case SIGINT:
            // 设置退出标志
            keep_running = 0;
            break;
        case SIGHUP:
            // 重新加载配置
            reload_config();
            break;
    }
}

signal(SIGTERM, signal_handler);
signal(SIGINT, signal_handler);
signal(SIGHUP, signal_handler);
```

**常用信号**：
- `SIGTERM`：终止信号，用于正常关闭守护进程
- `SIGINT`：中断信号（Ctrl+C）
- `SIGHUP`：挂起信号，通常用于重新加载配置
- `SIGKILL`：强制终止信号（无法捕获）

### 8. 写入 PID 文件

**目的**：记录守护进程的 PID，便于管理和控制。

```c
int write_pid_file() {
    FILE *fp = fopen(PID_FILE, "w");
    if (fp == NULL) {
        return -1;
    }
    fprintf(fp, "%d\n", getpid());
    fclose(fp);
    return 0;
}
```

**用途**：
- 系统服务管理器（如 systemd）可以使用 PID 文件管理守护进程
- 便于查找和终止守护进程
- 防止多个守护进程实例同时运行

## 完整的守护进程创建函数

```c
int create_daemon() {
    pid_t pid;

    // 1. 第一次fork
    pid = fork();
    if (pid < 0) {
        perror("fork");
        return -1;
    }
    if (pid > 0) {
        exit(EXIT_SUCCESS);
    }

    // 2. 创建新会话
    if (setsid() < 0) {
        perror("setsid");
        return -1;
    }

    // 3. 第二次fork
    pid = fork();
    if (pid < 0) {
        perror("fork");
        return -1;
    }
    if (pid > 0) {
        exit(EXIT_SUCCESS);
    }

    // 4. 改变工作目录
    if (chdir("/") < 0) {
        perror("chdir");
        return -1;
    }

    // 5. 设置文件权限掩码
    umask(0);

    // 6. 关闭文件描述符
    close(STDIN_FILENO);
    close(STDOUT_FILENO);
    close(STDERR_FILENO);

    open("/dev/null", O_RDONLY);
    open("/dev/null", O_WRONLY);
    open("/dev/null", O_WRONLY);

    return 0;
}
```

## 守护进程的日志记录

由于守护进程没有控制终端，需要将日志写入文件：

```c
void write_log(const char *message) {
    FILE *log_fp = fopen(LOG_FILE, "a");
    if (log_fp) {
        time_t now = time(NULL);
        char *time_str = ctime(&now);
        time_str[strlen(time_str) - 1] = '\0'; // 移除换行符
        fprintf(log_fp, "[%s] %s\n", time_str, message);
        fclose(log_fp);
    }
}
```

## 守护进程的管理

### 启动守护进程

```bash
# 直接运行（会在后台运行）
./daemon_server

# 或者使用 nohup
nohup ./daemon_server &
```

### 查看守护进程

```bash
# 查看进程
ps aux | grep daemon_server

# 查看PID文件
cat /tmp/daemon_server.pid

# 查看日志
tail -f /tmp/daemon_server.log
```

### 停止守护进程

```bash
# 方法1：使用PID文件
kill $(cat /tmp/daemon_server.pid)

# 方法2：发送SIGTERM信号
kill -TERM $(cat /tmp/daemon_server.pid)

# 方法3：查找进程并终止
pkill daemon_server

# 方法4：强制终止（不推荐）
kill -9 $(cat /tmp/daemon_server.pid)
```

### 重新加载配置

```bash
# 发送SIGHUP信号，让守护进程重新加载配置
kill -HUP $(cat /tmp/daemon_server.pid)
```

## 守护进程 vs 普通进程

| 特性 | 普通进程 | 守护进程 |
|------|---------|---------|
| 运行方式 | 前台或后台 | 后台 |
| 控制终端 | 有 | 无 |
| 终端关闭 | 进程终止 | 继续运行 |
| 标准输入输出 | 终端 | /dev/null 或日志文件 |
| 启动方式 | 用户启动 | 系统启动或用户启动 |
| 生命周期 | 用户会话期间 | 系统运行期间 |

## 守护进程的最佳实践

### 1. 错误处理

- 所有系统调用都应该检查返回值
- 记录错误日志
- 优雅处理错误情况

### 2. 资源管理

- 及时释放不需要的资源
- 避免内存泄漏
- 正确关闭文件描述符

### 3. 信号处理

- 正确处理所有相关信号
- 实现优雅退出
- 支持配置重载

### 4. 日志记录

- 记录重要事件
- 包含时间戳
- 适当的日志级别

### 5. 安全性

- 使用最小权限原则
- 避免以 root 用户运行（如果可能）
- 验证输入数据

## 使用 systemd 管理守护进程

现代 Linux 系统通常使用 systemd 管理守护进程。可以创建 systemd 服务文件：

```ini
[Unit]
Description=Daemon Server
After=network.target

[Service]
Type=forking
ExecStart=/usr/local/bin/daemon_server
PIDFile=/tmp/daemon_server.pid
Restart=always

[Install]
WantedBy=multi-user.target
```

然后使用 systemctl 管理：

```bash
# 启动服务
sudo systemctl start daemon_server

# 停止服务
sudo systemctl stop daemon_server

# 查看状态
sudo systemctl status daemon_server

# 开机自启
sudo systemctl enable daemon_server
```

## 常见问题

### 1. 为什么需要两次 fork？

- 第一次 fork：让父进程退出，使子进程成为孤儿进程
- 第二次 fork：确保进程不是会话组长，无法重新获取控制终端

### 2. 为什么需要调用 setsid()？

- 创建新的会话，脱离原来的控制终端
- 使进程成为新会话的会话组长

### 3. 为什么要改变工作目录？

- 避免工作目录被占用，导致文件系统无法卸载
- 通常改为根目录 `/`

### 4. 为什么要关闭文件描述符？

- 关闭从父进程继承的文件描述符
- 重新打开标准输入输出到 `/dev/null`
- 防止 I/O 操作影响终端

### 5. 如何测试守护进程？

- 使用客户端连接测试
- 查看日志文件
- 发送信号测试信号处理

## 总结

守护进程是 Linux 系统中重要的后台服务进程。创建守护进程需要遵循标准的步骤，包括两次 fork、调用 setsid、改变工作目录、设置文件权限掩码、关闭文件描述符等。守护进程应该正确处理信号、记录日志、管理资源，以确保稳定可靠的运行。
