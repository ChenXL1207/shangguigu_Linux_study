# 信号处理机制说明

## signal_handler 函数什么时候被调用？

`signal_handler` 函数在以下情况下会被调用：

### 1. 用户按下 Ctrl+C (SIGINT 信号)
当程序运行时，如果用户在终端按下 `Ctrl+C`，系统会向程序发送 `SIGINT` 信号，此时会触发 `signal_handler` 函数。

**示例：**
```bash
# 启动服务器
./build/socket_ipc_communication.out server
启动服务器
# 用户按下 Ctrl+C
^C  # 此时会调用 signal_handler
```

### 2. 系统发送终止信号 (SIGTERM)
当系统或其他程序向你的程序发送 `SIGTERM` 信号时（例如使用 `kill` 命令），会触发 `signal_handler` 函数。

**示例：**
```bash
# 启动服务器
./build/socket_ipc_communication.out server &
SERVER_PID=$!

# 使用 kill 命令终止程序
kill $SERVER_PID  # 此时会调用 signal_handler
```

### 3. 信号注册机制

在代码中，我们通过以下方式注册信号处理函数：

```c
signal(SIGINT, signal_handler);   // 注册 Ctrl+C 信号处理
signal(SIGTERM, signal_handler);  // 注册终止信号处理
```

这意味着：
- 当程序收到 `SIGINT` 信号时，会调用 `signal_handler`
- 当程序收到 `SIGTERM` 信号时，会调用 `signal_handler`

## cleanup_socket 函数什么时候被调用？

`cleanup_socket` 函数在以下情况下会被调用：

### 1. 程序正常退出时 (atexit)
通过 `atexit(cleanup_socket)` 注册，当程序正常退出（`return 0` 或 `exit(0)`）时，会自动调用 `cleanup_socket`。

**示例：**
```c
// 在 main 函数中注册
atexit(cleanup_socket);

// 当程序执行到 return 0 时，会自动调用 cleanup_socket
return 0;
```

### 2. 信号处理函数中调用
`signal_handler` 函数内部会调用 `cleanup_socket`，确保在收到信号时也能清理资源。

```c
void signal_handler(int sig)
{
    cleanup_socket();  // 清理资源
    exit(0);           // 退出程序
}
```

## 完整的清理流程

### 场景 1：正常退出
```
程序运行 → 执行到 return 0 → atexit 调用 cleanup_socket → 清理 socket 文件 → 程序退出
```

### 场景 2：用户按 Ctrl+C
```
程序运行 → 用户按 Ctrl+C → 系统发送 SIGINT → signal_handler 被调用 → 
调用 cleanup_socket → 清理 socket 文件 → exit(0) → 程序退出
```

### 场景 3：使用 kill 命令
```
程序运行 → kill 命令发送 SIGTERM → signal_handler 被调用 → 
调用 cleanup_socket → 清理 socket 文件 → exit(0) → 程序退出
```

## 为什么需要信号处理？

1. **防止资源泄漏**：如果程序异常退出（如被强制终止），socket 文件可能不会被删除
2. **确保清理**：无论程序如何退出，都能确保清理资源
3. **避免"Address already in use"错误**：下次启动时不会因为旧的 socket 文件而失败

### 测试 Ctrl+C
```bash
# 终端 1：启动服务器
./build/socket_ipc_communication.out server

# 按 Ctrl+C，观察 socket 文件是否被删除
ls -la unix_domain.socket  # 应该不存在
```

```bash
./build/socket_ipc_communication.out server &
SERVER_PID=$!

# 发送 SIGTERM 信号
kill $SERVER_PID

# 检查 socket 文件是否被删除
ls -la unix_domain.socket  # 应该不存在
```
